# CMAMS V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the approved single-church online attendance MVP with an adapted shadcn-admin frontend, secure API, Supabase migration, and safe deployment path.

**Architecture:** Start from the actual MIT-licensed shadcn-admin source, preserving its responsive layout and components while removing demo screens. Use a Vite SPA and Node/TypeScript Vercel functions for authenticated operations; the service role connects exclusively from the API. PostgreSQL constraints and a hardened check-in RPC enforce attendance invariants.

**Tech Stack:** Node 22+, React 19, TypeScript, Vite, shadcn/ui, Tailwind 4, TanStack Router/Query, Vercel functions, Supabase PostgreSQL, Vitest.

## Global Constraints

- One church only: no campuses table, `campus_id`, campus switcher, or campus filter.
- Never store QR plaintext tokens in the database or browser persistent storage; never send Supabase service credentials to the browser.
- V1 is online-only: network failures cannot be reported as successful check-ins.
- Staff-only sign-in with HttpOnly Secure SameSite cookies; validate mutations and enforce server RBAC.
- One attendance record per `(service_id, person_id)`; one active QR card per person; preserve historical attendance snapshots.
- No production rollout or deletion of `gracearenamegayouthchurch/cmams` before a locally verified replacement is ready.

## File map

- `src/routes/`, `src/features/cmams/`, `src/components/layout/`: shadcn-admin navigation, signed-in shell and CMAMS screens.
- `src/lib/cmams-api.ts`: typed browser HTTP boundary and errors.
- `api/index.ts`: Vercel catch-all entry, delegating to `server/app.ts`.
- `server/auth.ts`, `server/rbac.ts`, `server/db.ts`: sessions, authorization, server-only SQL access.
- `server/people.ts`, `server/cards.ts`, `server/services.ts`, `server/checkins.ts`, `server/reports.ts`: focused domain actions.
- `supabase/migrations/001_cmams.sql`: tables, constraints, RLS, RPC, indexes.
- `scripts/bootstrap-admin.ts`: secure one-time admin creation.
- `server/*.test.ts`, `src/features/cmams/*.test.tsx`: behavior and permissions.
- `.env.example`, `vercel.json`, `README.md`: safe setup and existing-project deployment.
